# Ask Implementation Plan

**Goal:** Answer a question from the hadith the app already retrieves, on-device, without ever letting the model produce scripture.

**Architecture:** `SearchEngine` retrieves candidates; a `LanguageModelSession` returns a `@Generable` struct of *indices plus a summary*; a pure `AnswerValidator` enforces the safety rules; the app renders the real narrations from SQLite. Every failure path collapses to "no summary, plain results".

**Tech Stack:** FoundationModels (iOS 26), Swift 6 strict concurrency, swift-testing, SwiftUI.

Spec: `docs/superpowers/specs/2026-08-18-ask-design.md`

## Global Constraints

- **The model never emits narration text.** It returns indices into a candidate list. If a change would let a narration's text come out of the model, it is wrong.
- HadithKit stays UI-free. FoundationModels code is `@available(iOS 26.0, macOS 26.0, *)`; the package's iOS 18 floor does not move.
- `SWIFT_STRICT_CONCURRENCY: complete`.
- Engine tests are swift-testing; UI tests are XCTest.
- `xcodegen generate` after adding a file. Commands run from `apps/ios`.
- Known flake: `SQLite error 10` on FTS5 suites, ~1 in 5, pre-existing. Erase the simulator and re-run.
